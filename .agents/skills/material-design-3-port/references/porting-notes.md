# 移植時の判断と検証

## 世代と出典

MD3 ベースラインを基本とし、Expressive は対象機能として求められた範囲を扱う。生成トークンに項目が存在することと、部品でその項目を使うことを区別する。基本のタイプスケールに Emphasized を自動的に混ぜたり、押下時の形状モーフを移植範囲に追加したりしない。

既存の出典コメントが submodule の HEAD と異なる場合は、そのコミットを `git show <commit>:<path>` で読む。オブジェクトがローカルにない場合は未確認と記録し、HEAD の内容をそのコミットの根拠として扱わない。

出典を対応表にまとめる場合は、次の項目を残す。

| 項目   | 記録内容                                                 |
| ------ | -------------------------------------------------------- |
| 移植先 | Rust の定数・型・関数                                    |
| 値・式 | 単位、ロール、複合値の内訳                               |
| 移植元 | リポジトリ、相対パス、シンボル。行番号は補助として使う   |
| 版     | コミット SHA、トークンの VERSION / design system version |
| 判断   | 他の実装との相違、GPUI 向けの変換、未対応事項            |

## トークンを変換するとき

- **色**: コンテナ・内容・状態レイヤーの色を別々に追う。disabled のコンテナ不透明度は部品ごとに確認し、共通の値に置き換えない。トークンとコンポーネントの defaults が違えば、実際の適用箇所を読んで採用理由を残す。
- **形**: `Corner*Top` / `Corner*End` / `corner-large-start` のような部分的な角丸は、半径と適用する角を保持する。start / end と左右の対応は RTL を含めて確認する。Full を固定半径として転記しない。
- **書体**: sp、行高、tracking、ウェイトを別々に扱う。描画 API が反映できない属性は未対応として記録する。フォントはシステムフォントやテーマ指定との対応を確認し、参照実装と同じフォントがあると仮定しない。
- **寸法**: dp / sp / CSS px / GPUI の論理ピクセル / 物理ピクセルを区別する。テーマの密度・文字倍率と、ウィンドウのスケール係数を重複して掛けない。最小高、固定高、最小操作領域、アイコン枠を混同しない。
- **余白**: コンポーネント実装のアイコン有無・ラベル有無・精密ポインタなどの分岐を読む。例えば TextField はアイコンの操作領域と表示サイズの差が文字位置の計算に関わる。
- **影・フォーカス指標**: elevation の数値だけでは影の描画パラメータは決まらない。Compose がプラットフォームに委譲している値は material-web の実装を確認する。

## 計算と状態を移植するとき

- バネは減衰比と減衰係数を区別し、剛性・質量・初期速度・時間単位を照合する。`md3-theme` の変換と固定版 GPUI の解析解を先に確認し、Compose の `SpringSimulation.updateValues` と同じ入力で位置・速度を比較する。減衰不足・臨界・過減衰、時刻 0、目標値への収束を対象の式に応じて検証する。
- Standard / Expressive と Fast / Default / Slow、Spatial / Effects の選択は部品側の呼び出しまで追う。トークンの数値が同じでも、選ぶ種類が異なれば同じ動きにはならない。
- リップルは半径・直径・scale の定義、bounded / unbounded、クリップ、中心の移動、早い解放や取消しを確認する。
- 値の範囲と丸め、NaN などの入力契約、分母が 0 になる条件は、その関数が受け付ける入力に即して確認する。許容誤差は上流の精度と表示上の意味から決める。
- 状態が同時に成立する場合の優先順位を確認する。hover / focus / press の不透明度を単純に足さず、上流の状態選択と合成方法を読む。
- reduce motion の動作と、フォーカス喪失・無効化・取消し後に押下やアニメーション状態が残らないことを確認する。

## 実装結果の確認

純粋な計算は上流の fixture や独立した式で検証する。寸法・折り返し・操作領域が変わる場合は、利用可能なら GPUI の描画テストでも確認する。文字を持つ部品は文字倍率 100% / 200% で、固定寸法が切れや重なりを生まないかを見る。画面を確認できなければ、目視済みとは報告しない。

`cargo test -p <変更したcrate>` など、現在の workspace に存在するチェックを選ぶ。見本アプリや開発用コマンドを使うときは、実装と実行方法を確認する。
