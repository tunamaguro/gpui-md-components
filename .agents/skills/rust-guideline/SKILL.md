# Rust

- 基本的に`#![forbid(unsafe_code)]`,`#![deny(missing_docs)]`を使用する
- linterの警告を抑制する必要があるときは、`#[allow(...)]` ではなく `#[expect(..., reason = "...")]` を使う
  - `#[allow(...)]`ではそのlint項目がなくなったり、コード変更によって不要になった時に気づけないため
  - 理由は必ず記述する
- `.unwrap()`ではなく`.expect("message")`を使用する
  - `.expect("MESSAGE")` を使用して、最低限「このパニックが状況によっては発生する可能性がある」のか、それとも「絶対に発生しない想定（発生した場合は実装バグ）」なのかがメッセージから分かるようにすること
  - ただし、できる限りパターンマッチ等を利用してOption,Result等を避けること
- 複雑な状態には`enum`を活用すること
  - 1つの構造体に根本的に異なる状態を持たせず、不正な状態をコンパイル時に排除すること
  - 目安として、同じフィールドに対して繰り返し`if let`や`match`を行っている場合は複数状態が存在する可能性があるので、`enum`を検討する
