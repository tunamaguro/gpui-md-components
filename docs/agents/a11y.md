# アクセシビリティ規約と検証手順

## 従う資料

a11y の判断は推測で決めず、次の資料に従う（場所とライセンスは `resources.md`）。

| 資料                                                                                                                                                                                                                  | 何を決めるか                                                                                                                           |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Material Design 3（m3.material.io の Foundations > Accessibility と各コンポーネントの Accessibility タブ）                                                                                                            | 部品ごとの a11y 要件（ラベル、操作できる範囲、フォーカスの順、タッチ領域）                                                             |
| WCAG 2.2（https://www.w3.org/TR/WCAG22/）                                                                                                                                                                             | 満たす基準（AA）。コントラスト（1.4.3 / 1.4.11）、フォーカス可視（2.4.7）、フォーカスが隠れない（2.4.11）、名前・役割・値（4.1.2）など |
| WAI-ARIA APG（https://www.w3.org/WAI/ARIA/apg/patterns/）                                                                                                                                                             | 役割・状態の付け方とキー操作（下表）                                                                                                   |
| Compose foundation text input（`docs/references/androidx` の `compose/foundation/foundation/src/commonMain/kotlin/androidx/compose/foundation/text/input/internal/TextFieldDecoratorModifier.kt` の `onFocusChange`） | 要素のフォーカス喪失では変換を終了して文字を残し、ウィンドウのフォーカス喪失だけでは終了しない                                         |
| Apple `NSTextInputClient.unmarkText()`（https://developer.apple.com/documentation/appkit/nstextinputclient/unmarktext()）                                                                                             | マークを外した文字は通常の挿入と同様に受け入れる                                                                                       |
| W3C UI Events §3.6（https://www.w3.org/TR/uievents/）                                                                                                                                                                 | composition イベント。フォーカス喪失時の確定か取消しかは定めていない                                                                   |
| Microsoft `ImmNotifyIME`（https://learn.microsoft.com/en-us/windows/win32/api/imm/nf-imm-immnotifyime） / TSF Compositions（https://learn.microsoft.com/en-us/windows/win32/tsf/compositions）                        | 変換を終了する API。フォーカス喪失時の義務は記載されていない                                                                           |

MD3・WCAG・APG には IME 変換の終了に関する定めが見つからなかったため、上記の資料に従う。移植元の Compose を最優先する。

食い違ったら WCAG 2.2（満たすべき基準）を最優先し、振る舞いは MD3、役割・状態・キー操作は APG に合わせる。
どの資料のどの項に従ったかを、PR と `docs/specs/<component>.md` に書く。

## 実装規約

GPUI は AccessKit で OS のアクセシビリティ API（macOS: NSAccessibility、Windows: UI Automation、Linux: AT-SPI）に情報を渡す。Web（wasm32）では渡さない（下記の制約）。
コンポーネント側の責任は次の 4 つ。

1. **安定 ID**: 操作可能な要素はすべて `ElementId` を持つ。フレームをまたいで同じ要素には同じ ID を付ける（ID が変わると別要素と見なされ、読み上げ位置が飛ぶ）。リストの項目は index ではなくデータのキーから ID を作る。
1. **役割（role）**: 役割のない要素はツリーに出ない。APG のパターンに対応する役割を付ける（下表）。
1. **名前・状態**: 名前は表示ラベル、アイコンのみなら必須のラベル引数。状態（checked、toggled、expanded、selected、disabled、value）を毎フレーム反映する。
1. **アクション**: クリック相当以外の操作（increment / decrement 等）は `on_a11y_action` で受ける。

GPUI の API 名（`.role()`, `.aria_label()`, `.aria_toggled()`, `.on_a11y_action()`, `Element::a11y_synthetic_children`）は固定 rev のソースで確認すること。
a11y 付与は `gpui-headless` の `A11yExt` トレイトに集約する。headless 側が役割・名前・状態を組み立て、MD3 側は見た目を付ける。

## フォーカス

- フォーカスリングはキーボード操作時に必ず描く。色・太さは MD3 の focus indicator 仕様に従う（太さ 3dp、外側オフセット 2dp。値は resources.md の資料で確認）。
- キーボードでフォーカスが移った要素は `ScrollScope` 内で自動的に表示する（WCAG 2.2 の 2.4.11）。外側のリング分も確保し、
  入れ子は内側から調整する。領域より大きな要素は先頭を合わせ、スクロール限界では可能な範囲まで動かす。
  マウスクリックでは動かさず、ホイールで離してもフォーカスが同じなら引き戻さない。独自要素には `reveal_on_focus` を付ける。

### キーボードフォーカス順序の方針

- Tab 順は要素ツリーの順（描画順）で決まる。レイアウトを組むときに、視覚的な読み順（左から右、上から下）とツリーの順を一致させる。`tab_index` で順序を入れ替えない。
- Tab で止まるのは操作できる要素だけ。装飾・見出し・静的な文字はフォーカスを持たない。
- 複合部品（RadioGroup、SegmentedButton、Tabs、Menu、List）は部品全体で Tab の止まり場所を 1 つにし、中の移動は矢印キーで行う（roving tabindex）。止まる位置は選択中の項目、無ければ先頭。
- 無効状態の要素は Tab で止まらない。
- フォーカスリングは `gpui_headless::is_focus_visible` で、キーボードによるフォーカス中はマウス移動後も描く。フォーカスを失うと消し、共通の操作要素と Card はクリックでも消す。
- `RenderOnce` の部品は `gpui_headless::focus_handle(id, …)` で ID に結び付いたフォーカスハンドルを使い、描画をまたいでフォーカスを保つ。
- gpui は Tab キーに既定の動作を持たないため、アプリ側で `tab` / `shift-tab` を `window.focus_next` / `focus_prev` に割り当てる（gallery を参照）。
- 部品のキー割り当て（テキストフィールドの編集、オーバーレイの Esc と Tab）は `md3_components::init`（テーマの初期化後に `gpui_headless::init` を呼ぶ） が部品のキーコンテキスト付きで行う。コンテキストのない割り当てと同じ優先度になるため、アプリの割り当ての後で `init` を呼ぶ。
- オーバーレイ（Menu、Dialog、モーダルな Sheet）は開いたとき中の最初の要素（Menu は選択中の項目）にフォーカスし、閉じたら開いた要素にフォーカスを戻す。Dialog と Sheet は Tab を中で回し、Menu は Tab で閉じる。

## IME

- 未確定の文字は、要素のフォーカスが失われたとき、またはユーザーがクリックしたときに、破棄せず確定する。ウィンドウのフォーカスだけが失われたときは未確定のままにする。

## モーション

- 動きは gpui の `App::reduce_motion`（OS の「視差効果を減らす」相当）に従う。gpui は OS の設定を読まないため、
  アプリが起動時と設定の変更時に `cx.set_reduce_motion(..)` を呼ぶ（gallery はデスクトップで `MD3_REDUCE_MOTION=1`、
  Web で `prefers-reduced-motion`）。
- 部品のバネ（形・幅・位置・色の変化）は gpui の `with_spring` で描き、`reduce_motion` なら動かさずに最終の状態で描く。
  押下の形を見せるための待ちもしない。gpui の `with_animation`（Progress の不確定の動きなど）も止まる。

## コントラスト

- テーマ生成時のスキームは HCT のトーン差で保証されるが、利用者の色上書きで崩れる可能性がある。`Theme::check_contrast()` で検出する。
- 基準: 本文 4.5:1、大きい文字と UI 部品の境界 3:1（WCAG 2.2）。

## 検証手順（3 段階）

スクリーンリーダーに詳しくなくても回せるよう、手作業は最後の確認に限定する。

### 1. 自動テスト（毎 PR、必須）

現状（gpui @ 37faef81）の制約と対応:

- gpui のテスト用プラットフォームは AccessKit を有効化しないため、テストからツリーそのものは取得できない。
  そこで部品ごとに `a11y_node()`（役割・名前・状態を組み立てる純関数、`A11yExt` で要素に当てるものと同じ）を公開し、
  `crates/gpui-headless/tests/` でその値を、部品の組み合わせは `crates/md3-components/tests/` で確かめる。どちらも値と、`TestAppContext` でのキー操作（Tab での到達、Enter / Space / 矢印 / Home / End など）後の状態変化を検証する。

- gpui の要素の API（`aria_*`）に無い状態は、`a11y_synthetic_children` で渡される要素自身の AccessKit のノード
  （`gpui::accesskit`）に `A11yExt` が直接書く: 無効（disabled）、modal、入力エラー（invalid）、live region（polite）。

- 無効な部品は Tab でも止まらない。Linux（AT-SPI）では AccessKit が読み取り専用を持てる役割
  （Checkbox / RadioButton / Switch / Slider / テキスト入力 / ComboBox など）でしか無効を伝えないため、
  ボタン・タブ・リスト項目の無効は Linux のスクリーンリーダーには伝わらない（`accesskit_atspi_common` 0.19）。
  invalid も AT-SPI には出ない。

- gpui はフォーカスされた要素で Enter と Space の両方をクリックとして扱うため、Checkbox / Switch は Enter でも切り替わる。

- Snackbar は役割 Status・live region（polite）で出す。表示時に読み上げられるかはリーダー次第（`docs/a11y-audit.md`）。

- Dialog / モーダルな Sheet / Drawer は modal の印を付ける（見本用の `inline()` では付けない）。後ろの要素はツリーに残る
  （フォーカスとマウスは届かない）。

- gpui のツールチップはポインタを重ねたときだけ出る。`md3_tooltip` は基準の要素の説明（description）にも同じ文を入れて代える。

- TextField / Select のエラーは invalid として出す。gpui には required の印がない。エラーの理由は補助テキストに書く。

- テキストフィールドの書記素の境界は簡易判定（依存を増やせないため）。

- wasm では OS を区別できないため、編集のショートカットは Ctrl を使う（macOS のブラウザでも Ctrl）。

- **wasm では gpui が AccessKit を組み込まない**（`gpui/src/window.rs` の `#[cfg(not(target_family = "wasm"))]`）。
  Web ではアクセシビリティツリーが無く、スクリーンリーダーは部品を読めない。

- アクセシビリティが有効なとき、1 つのフォーカスハンドルを 2 つの要素が追跡すると gpui のデバッグビルドが panic する
  （同じ ID・同じ `TextFieldState` を 2 か所に描かない）。

- テストは gpui の `test-support`（各 crate の dev-dependency。追加の crate ではない）で部品を描く。
  共通の補助は各 crate の `tests/support/`（`open` で部品 1 つを描くウィンドウを開き、キー・マウスのイベントを送る）。

- assert する項目: `a11y_node()` の役割・名前・状態、キー入力後の状態変化、フォーカスの移動先。

- コンポーネントごとに該当 crate の `tests/` にテストを作る（まとめた `navigation.rs` / `overlays.rs` もある）。

### 2. ツリー目視（部品追加時、推奨）

OS 付属の検査ツールで gallery を開き、部品が正しい役割と名前で出ているかを見る。
Linux では `nix develop -c tools/a11y-tree/run.sh` で全ページの AT-SPI のツリーをファイルに書き出せる（`docs/a11y-audit.md`）。

- macOS: Xcode 付属の Accessibility Inspector
- Windows: Accessibility Insights for Windows（無料）
- Linux: Accerciser

### 3. 読み上げ確認（リリース前、必須）

必須のスクリーンリーダー（各 OS 標準）:

| OS      | リーダー                         | 起動                            |
| ------- | -------------------------------- | ------------------------------- |
| macOS   | VoiceOver                        | Cmd + F5                        |
| Windows | Narrator                         | Ctrl + Win + Enter              |
| Linux   | Orca                             | GNOME の設定 > アクセシビリティ |
| Web     | 上記 + Chrome / Firefox / Safari | —                               |

推奨: NVDA（Windows、無料）。

部品ごとのチェック項目:

1. Tab でその部品に移動できる
1. 役割と名前が読まれる（例: 「保存、ボタン」）
1. 状態が読まれる（例: 「チェック済み」）
1. Space / Enter / 矢印で操作でき、変化後の状態が読まれる
1. 無効状態ではそれが伝わる

結果は `docs/a11y-audit.md` に OS × 部品の表で記録する。チェックリストは本ファイルの役割・キー操作表から生成する。
