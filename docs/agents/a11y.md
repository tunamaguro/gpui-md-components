# アクセシビリティ規約と検証手順

## 実装規約

GPUI は AccessKit で OS のアクセシビリティ API（macOS: NSAccessibility、Windows: UI Automation、Linux: AT-SPI、Web: ブラウザ）に情報を渡す。
コンポーネント側の責任は次の 4 つ。

1. **安定 ID**: 操作可能な要素はすべて `ElementId` を持つ。フレームをまたいで同じ要素には同じ ID を付ける（ID が変わると別要素と見なされ、読み上げ位置が飛ぶ）。リストの項目は index ではなくデータのキーから ID を作る。
2. **役割（role）**: 役割のない要素はツリーに出ない。APG のパターンに対応する役割を付ける（下表）。
3. **名前・状態**: 名前は表示ラベル、アイコンのみなら必須のラベル引数。状態（checked、toggled、expanded、selected、disabled、value）を毎フレーム反映する。
4. **アクション**: クリック相当以外の操作（increment / decrement 等）は `on_a11y_action` で受ける。

GPUI の API 名（`.role()`, `.aria_label()`, `.aria_toggled()`, `.on_a11y_action()`, `Element::a11y_synthetic_children`）は固定 rev のソースで確認すること。
a11y 付与は `md3-components` 内部の `A11yExt` トレイトに集約し、API 変更の影響を局所化する。

## 部品ごとの役割とキー操作（APG 準拠）

| 部品 | 役割 | 状態 | キー操作 |
| --- | --- | --- | --- |
| Button / IconButton / FAB | Button | disabled | Enter, Space で実行 |
| Toggle IconButton | Button（toggled） | toggled | Enter, Space で切替 |
| Checkbox | CheckBox | checked（true / false / mixed） | Space で切替 |
| RadioButton | RadioButton（グループは RadioGroup） | checked | 矢印でグループ内移動と選択、Tab でグループ外へ |
| Switch | Switch | toggled | Space で切替 |
| Slider | Slider | value, min, max | 矢印で 1 ステップ、Page Up/Down で大きく、Home/End で端 |
| SegmentedButton | RadioGroup または Group + Button（toggled） | selected | 矢印で移動 |
| Chip（Filter） | CheckBox 相当 | checked | Space |
| TextField | TextInput | value, invalid, required | 通常の文字入力、IME |
| Menu | Menu / MenuItem | expanded（トリガー側） | 矢印で移動、Enter で実行、Esc で閉じる |
| Dialog | Dialog（modal） | — | Tab がダイアログ内で循環、Esc で閉じる、閉じたら呼び出し元にフォーカス |
| Tooltip | Tooltip | — | フォーカスでも表示、Esc で閉じる |
| Tabs | TabList / Tab / TabPanel | selected | 矢印で移動、Home/End |
| List | List / ListItem | selected | 矢印で移動 |
| Navigation 系 | Navigation + Link / Button | selected（現在地） | Tab または矢印 |
| Progress | ProgressIndicator | value（不定なら無し） | — |

## フォーカス

- フォーカスリングはキーボード操作時に必ず描く。色・太さは MD3 の focus indicator 仕様に従う（太さ 3dp、外側オフセット 2dp。値は resources.md の資料で確認）。
- Tab 順は視覚的な順序と一致させる。`tab_index` で順序を入れ替えない。
- オーバーレイ（Menu、Dialog、Sheet）は開いたとき中にフォーカスを移し、閉じたら元に戻す。

## コントラスト

- テーマ生成時のスキームは HCT のトーン差で保証されるが、利用者の色上書きで崩れる可能性がある。`Theme::check_contrast()` で検出する。
- 基準: 本文 4.5:1、大きい文字と UI 部品の境界 3:1（WCAG 2.2）。

## 検証手順（3 段階）

スクリーンリーダーに詳しくなくても回せるよう、手作業は最後の確認に限定する。

### 1. 自動テスト（毎 PR、必須）

- gpui の test-support 機能で部品を描画し、アクセシビリティを強制有効化（`with_accessibility_forced` 相当、要確認）した状態でツリーを取得する。
- assert する項目: 役割、名前、状態、キー入力後の状態変化、フォーカスの移動先。
- コンポーネントごとに `tests/a11y_<component>.rs` を作る。

### 2. ツリー目視（部品追加時、推奨）

OS 付属の検査ツールで gallery を開き、部品が正しい役割と名前で出ているかを見る。

- macOS: Xcode 付属の Accessibility Inspector
- Windows: Accessibility Insights for Windows（無料）
- Linux: Accerciser

### 3. 読み上げ確認（M7、必須）

必須のスクリーンリーダー（各 OS 標準）:

| OS | リーダー | 起動 |
| --- | --- | --- |
| macOS | VoiceOver | Cmd + F5 |
| Windows | Narrator | Ctrl + Win + Enter |
| Linux | Orca | GNOME の設定 > アクセシビリティ |
| Web | 上記 + Chrome / Firefox / Safari | — |

推奨: NVDA（Windows、無料）。

部品ごとのチェック項目:

1. Tab でその部品に移動できる
2. 役割と名前が読まれる（例: 「保存、ボタン」）
3. 状態が読まれる（例: 「チェック済み」）
4. Space / Enter / 矢印で操作でき、変化後の状態が読まれる
5. 無効状態ではそれが伝わる

結果は `docs/a11y-audit.md` に OS × 部品の表で記録する。チェックリストは本ファイルの役割・キー操作表から生成する。
